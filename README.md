# StudyCast

StudyCast — поиск по собственным аудиозаписям лекций.

Студент открывает запись занятия с телефона, приложение расшифровывает её прямо в браузере и показывает текст с таймкодами рядом с плеером. По тексту можно искать, переходить к нужному моменту аудио, ставить закладки с заметками и выгружать конспект в Markdown или SRT. Аудиофайл не покидает устройство: сервер хранит только текст расшифровок и нужен, чтобы открыть тот же конспект на втором устройстве по одноразовому коду. Регистрации нет.

> Статус: первая рабочая версия MVP (ЛР6). Работает основной сценарий без сервера: импорт аудио → расшифровка в браузере или импорт субтитров → поиск → переход к моменту → закладка с заметкой → экспорт в Markdown/SRT. Синхронизация между устройствами и backend — следующий этап.

## Запуск

### Приложение (frontend)

Нужен Node.js 20+.

```bash
cd frontend
npm install
npm run dev
```

Открыть http://localhost:5173. Проверка: `npm test` (unit-тесты), `npm run test:e2e` (e2e-тесты, см. раздел «Тесты»), `npm run build` (типы и production-сборка).

Демонстрационный сценарий: «Импортировать запись» → выбрать аудиофайл лекции → «Начать распознавание» (при первом запуске скачивается модель: ~115 МБ с WebGPU или ~40 МБ без него) → ввести слово в поиск по транскрипту → кликнуть по фразе → поставить закладку и написать заметку → «Экспорт» → Markdown. Вместо распознавания можно выбрать «Загрузить субтитры» и указать файл SRT/VTT — текст появится сразу. Распознавание быстрее всего работает в Chrome и Edge (WebGPU).

### Статическая страница (ЛР4–5)

Главная страница (HTML + CSS, ЛР4–5): открыть `tempPage/index.html` в браузере или запустить локальный сервер через uv:

```bash
uv run python -m http.server 8000 --directory tempPage
```

и открыть http://localhost:8000. Стили лежат в `tempPage/css/main.css`: токены из ТЗ, Flexbox и Grid, адаптивность на 768, 1024 и 1440 px, тёмная тема по системной настройке.

Backend (пока только заготовка пакета):

```bash
uv sync
uv run studycast
```

Запуск всего проекта через `docker compose up` — задача FE-043.

## Тесты

[![Frontend tests](https://github.com/SkyFallen196/StudyCast/actions/workflows/frontend-tests.yml/badge.svg)](https://github.com/SkyFallen196/StudyCast/actions/workflows/frontend-tests.yml)

Все команды выполняются из папки `frontend/` после `npm install`.

```bash
cd frontend
npm test                         # unit-тесты (Vitest), ~1 с
npx playwright install chromium  # один раз: браузер для e2e-тестов
npm run test:e2e                 # e2e-тесты (Playwright), ~10 с
```

`npm run test:e2e` сам запускает сервер разработки на http://localhost:5173 (или использует уже запущенный). Полезные варианты:

```bash
npx playwright test tests/e2e/search.spec.ts   # один файл
npx playwright test --headed                   # с видимым окном браузера
npx playwright test --ui                       # интерактивный режим с пошаговым просмотром
npx playwright show-report                     # HTML-отчёт после прогона
```

Тесты не скачивают модель распознавания: текст берётся из субтитров, а аудио (тишина нужной длины) генерируется в памяти. Каждый тест запускается в чистом профиле браузера с пустой IndexedDB. При push и pull request в `main` и `dev` тесты запускаются в GitHub Actions (`.github/workflows/frontend-tests.yml`).

### Какие требования проверяются

| Требование | Файл | Ожидаемое поведение |
|---|---|---|
| **F-06** Поиск по транскрипту и переход к моменту (ТЗ 11.2, приложение Б) | `tests/e2e/search.spec.ts` | Подсвечиваются только совпадения, счётчик «1 из 3»; регистр не важен, «е» = «ё»; Enter / Shift+Enter и кнопки переключают совпадения по кругу; при отсутствии совпадений — «Ничего не найдено»; очистка поля или Escape снимает подсветку; клик по фразе перематывает аудио на её начало с точностью до 1 с |
| **F-01, F-03** Импорт аудио и субтитров, проверка формы (ТЗ 5.2, 8.1) | `tests/e2e/import-validation.spec.ts` | Пустая форма — ошибки под полями, запись не создаётся; неподдерживаемый формат и субтитры без таймкодов отклоняются с понятным сообщением; для подходящего файла показана длительность и подставлено название; корректные файлы создают запись, она появляется в библиотеке |
| **F-07, F-08, F-09** Закладки, локальная библиотека, экспорт (ТЗ 5.2, 11.5) | `tests/e2e/bookmarks.spec.ts` | Закладка появляется в панели и на таймлайне; закладка и заметка сохраняются после перезагрузки, повторной обработки нет; заметка не теряется при немедленной перезагрузке; двойной клик не создаёт дубликат; Markdown содержит таймкод, фразу и заметку; удаление закладки и записи (с подтверждением) обновляет интерфейс; на телефоне нет горизонтальной прокрутки |

Unit-тесты (`src/lib/lib.test.ts`) проверяют разбор SRT/VTT, поиск, экспорт Markdown/SRT, форматирование времени и нарезку аудио по паузам.
